# S1-02 带 valid/ready 握手的同步 FIFO

## 实验目的

先进先出缓冲器（First In, First Out，FIFO）按数据写入的先后顺序输出数据，用于在处理速率不同或时序相互独立的两个模块之间暂存数据。FIFO 是 AI 加速器中最常用的基础模块之一，在本路线后续阶段中的应用如下：

| 阶段 | 应用 |
|---|---|
| S2 AXI 总线 | Vivado 提供的 AXI4-Stream Data FIFO IP 所实现的功能与本实验相同 |
| S3 HLS | `hls::stream<T>` 综合后的硬件实现为 FIFO；在 `#pragma HLS DATAFLOW` 区域中，各函数之间的数据通道亦以 FIFO 实现 |
| S5 DMA | DMA 以突发传输（burst）方式从 DDR 读取数据，计算单元则以自身的处理速率读取数据，FIFO 用于缓冲二者之间的速率差异 |
| S6 及以后 | 计算流水线的各级之间以 FIFO 解耦；某一级暂停时，其上游的数据暂存于 FIFO 中，不会丢失 |

valid/ready 握手是 AXI4-Stream 协议规定的数据传输机制，S2 的 AXI 总线、S3 的 HLS 接口与 S5 的 DMA 均以此为基础。

本实验的目标为：

1. 掌握同步 FIFO 的结构及其空满状态的判定方法；
2. 掌握 valid/ready 握手协议的时序规则。

## 背景知识

### FIFO 的软件实现与硬件实现

在数据结构中，FIFO 即队列。其常见的软件实现为环形缓冲区（ring buffer），由一个长度为 N 的数组以及队头、队尾两个下标构成，下标增至 N 时回绕至 0。硬件 FIFO 采用相同的组织方式，二者的对应关系如下：

| 比较项 | 软件环形缓冲区 | 硬件 FIFO |
|---|---|---|
| 数据存储 | 数组 `buf[N]` | 存储阵列 `reg [WIDTH-1:0] mem [0:DEPTH-1]` |
| 写入位置 | 队尾下标 `tail`，入队后执行 `tail = (tail + 1) % N` | 写指针 `wp`，每次写入后加 1。当 `DEPTH` 为 2 的幂时，指针加法的溢出即实现回绕，无需取模运算 |
| 读出位置 | 队头下标 `head` | 读指针 `rp` |
| 操作的执行方式 | 入队与出队是顺序执行的两次函数调用 | 写入与读出由并行工作的两部分电路完成，二者可在同一时钟上升沿处同时发生 |
| 满或空时的处理 | 入队或出队操作阻塞调用者，例如 Python 的 `queue.Queue(maxsize=N)` | 电路不存在阻塞机制，而是以输出信号指示当前不可操作：满时 `s_ready = 0`，空时 `m_valid = 0` |

存储阵列中并非所有单元都属于 FIFO 的内容。从读指针 `rp` 所指的单元起，至写指针 `wp` 所指的单元之前（不含该单元），这一区间内的数据已经写入而尚未读出，称为**有效数据**；有效数据的个数即为 FIFO 中的数据个数。区间之外的单元可能保存着已被读出的旧数据，或上电后的不确定值，它们不会被读出，并将被后续写入的数据覆盖。FIFO 中的数据个数为 0 时，称 FIFO 为**空**；数据个数等于 `DEPTH` 时，称 FIFO 为**满**。

以信号指示“当前不可操作”的机制称为反压（backpressure）。下游模块无法接收数据时，将 `ready` 置为 0；上游模块随之暂停发送，必要时也将其自身的 `ready` 置为 0。暂停条件由此沿数据通路逐级向上游传递，通路中的任何一级均不会丢失数据。

### valid/ready 握手协议

valid/ready 握手协议使用以下三个信号：

- `data`：由发送方驱动，承载待传输的数据。
- `valid`：由发送方驱动。`valid = 1` 表示 `data` 上的数据有效。
- `ready`：由接收方驱动。`ready = 1` 表示接收方在当前周期能够接收数据。

**传输的判定规则：在某一时钟上升沿处，若 `valid` 与 `ready` 均为 1，则该周期完成一次数据传输；否则该周期不发生传输。** 四种组合如下：

| `valid` | `ready` | 该周期的行为 |
|---|---|---|
| 1 | 1 | 完成一次传输 |
| 1 | 0 | 不发生传输。发送方须保持 `data` 不变，直至传输完成 |
| 0 | 1 | 不发生传输。发送方没有有效数据 |
| 0 | 0 | 不发生传输 |

下例中，接收方在周期 1 将 `ready` 置为 0，因此数据 B 在周期 1 未能传输；发送方在周期 2 继续保持 B，B 于周期 2 完成传输：

```
周期       0     1     2     3     4
valid      1     1     1     1     0
data       A     B     B     C     -
ready      1     0     1     1     1
完成传输   A     -     B     C     -
```

AXI4-Stream 协议规范在握手过程（handshake process）一节中，对发送方另有以下两项规定。连接 Vivado IP 时，必须满足这两项规定：

1. `valid` 的置位不得依赖于 `ready`。若发送方等待 `ready` 为 1 后才置位 `valid`，而接收方又等待 `valid` 为 1 后才置位 `ready`，则双方相互等待，形成死锁。与之相对，接收方允许等待 `valid` 为 1 后再置位 `ready`。
2. `valid` 一经置位，在本次传输完成之前不得撤销，`data` 亦不得改变。

本实验的验收测试在随机读写阶段有意违反第 2 项规定：上游的 `s_valid` 与 `s_data` 在每个周期随机取值。FIFO 仅在握手成立的时钟上升沿处采样 `s_data`，因此在此类激励下仍应保持正确。该测试用于检验设计的健壮性。

### FIFO 的两个握手端口

FIFO 同时作为上游的接收方与下游的发送方，因此具有两个相互独立的握手端口，各自包含一组 valid/ready 信号：

```
                 写入端口                            读出端口
         ──── s_valid ───▶ ┌────────────┐ ──── m_valid ───▶
  上游   ──── s_data  ───▶ │    FIFO    │ ──── m_data  ───▶   下游
         ◀─── s_ready ──── └────────────┘ ◀─── m_ready ────
```

| 端口 | 发送方 | 接收方 | `valid` 信号 | `ready` 信号 | 握手成立的条件 | 握手成立时的操作 |
|---|---|---|---|---|---|---|
| 写入端口 | 上游 | FIFO | `s_valid`（FIFO 的输入） | `s_ready`（FIFO 的输出） | `s_valid` 与 `s_ready` 均为 1 | `s_data` 写入 FIFO |
| 读出端口 | FIFO | 下游 | `m_valid`（FIFO 的输出） | `m_ready`（FIFO 的输入） | `m_valid` 与 `m_ready` 均为 1 | 队头数据出队 |

两个端口的握手分别判定，互不影响：同一时钟上升沿处，可以只有写入握手成立，可以只有读出握手成立，也可以二者同时成立。判定某一端口是否发生传输时，只能使用该端口的一对信号。例如 `s_valid` 只与 `s_ready` 构成握手，与 `m_ready` 无关。

### 空满状态的判定

FIFO 为空时，所有已写入的数据均已读出，写指针与读指针指向同一地址，即 `wp == rp`。FIFO 为满时，写指针比读指针多前进了 `DEPTH` 个位置，回绕之后同样有 `wp == rp`。因此，仅比较两个地址无法区分空与满，必须引入额外的信息。常用方法有以下两种，实验者可选用其中任意一种：

1. **计数器法**：设置计数器 `count`，记录 FIFO 中的数据个数。仅写入时 `count` 加 1，仅读出时减 1，同时写入与读出或二者均不发生时保持不变。`count == 0` 时为空，`count == DEPTH` 时为满。该方法逻辑简单，但需要额外的计数器及其加减法逻辑。
2. **扩展指针法**：指针宽度比地址宽度多 1 位，低位用作存储地址，最高位在指针每次回绕时翻转。两指针的所有位均相等时为空；低位相等而最高位不同时为满。例如，`DEPTH = 4` 时地址为 2 位、指针为 3 位，`wp = 3'b100`、`rp = 3'b000` 表示写指针比读指针多前进了 4 个位置，FIFO 为满。该方法无需计数器。Cummings 的异步 FIFO 论文即采用此方法，原因是在跨时钟域设计中，两个时钟域无法共同维护同一个计数器。

### 读出时序：标准模式与首字直通模式

FIFO 读出端的时序有以下两种，Xilinx FIFO Generator IP 对二者均提供支持：

- **标准模式**（standard mode）：下游发出读请求后，数据在下一个时钟周期出现在输出端，读延迟为一个周期。
- **首字直通模式**（First-Word Fall-Through，FWFT）：FIFO 非空时，队头数据已出现在输出端，下游在 `m_valid = 1` 时即可直接使用该数据。此行为与 valid/ready 握手的语义一致。

本实验采用首字直通模式，`m_data` 由组合逻辑从 `mem[rp]` 读出。具有组合读出端口的存储阵列在 Vivado 中由查找表实现，称为分布式 RAM（distributed RAM）。深度较大（例如上千项）的 FIFO 通常以块 RAM（Block RAM）实现；块 RAM 的读出需要一个时钟周期，因此以块 RAM 实现首字直通模式时，须增加一级输出寄存器及相应的控制逻辑。两种存储资源的比较见 S2。

## 规格

### 握手规则

与 AXI4-Stream 协议一致：

1. 发送方以 `valid = 1` 表示数据有效，接收方以 `ready = 1` 表示能够接收数据。
2. 当且仅当某一时钟上升沿处 `valid` 与 `ready` 均为 1 时，该周期完成一次传输。

### 写入端（上游 → FIFO）

1. 当且仅当 FIFO 未满时，`s_ready = 1`。
2. 若上升沿处 `s_valid` 与 `s_ready` 均为 1，则 `s_data` 写入队尾。
3. FIFO 满时不接受写入：即使下游在同一周期读出数据，`s_ready` 仍为 0。该规定简化了实现，验收测试据此进行检查。

### 读出端（FIFO → 下游）

1. 当且仅当 FIFO 非空时，`m_valid = 1`。
2. FIFO 非空时，`m_data` 恒等于队头数据（首字直通模式）。
3. 若上升沿处 `m_valid` 与 `m_ready` 均为 1，则队头数据出队。

### 其他

1. 同一周期内可以同时写入与读出，此时 FIFO 中的数据个数不变。
2. `rst` 为同步复位，高电平有效。复位后 FIFO 为空，即 FIFO 中的数据个数为 0，此时 `m_valid = 0`、`s_ready = 1`。复位只需将指针（采用计数器法时还包括计数器）清零；存储阵列中残留的数据均位于有效数据区间之外，不会被读出，因此存储阵列本身无需复位。
3. 参数 `DEPTH` 须为 2 的幂。验收测试采用 `DEPTH = 16`、`WIDTH = 8`。

## 常见错误

- 读写指针的回绕处理有误，或回绕之后的空满判定有误。典型现象为自第 16 个数据前后开始出现错误。
- 在组合逻辑中对 `mem` 赋值，或在时序逻辑中使用阻塞赋值 `=`。
- FIFO 满时 `s_ready` 依赖于 `m_ready`，与本实验的规格不符。
