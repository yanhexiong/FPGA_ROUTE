# S1-02 带 valid/ready 握手的同步 FIFO

## 为什么做这个

加速器里到处都是 FIFO：DMA 搬来的数据先进 FIFO，计算单元按自己的节奏取；结果再进 FIFO 等着写回内存。
valid/ready 握手是 AXI-Stream 的核心规则，S2 学 AXI、S3 写 HLS 接口、S5 接 DMA 时都会反复用到。这个实验同时练这两样。

## 你要写什么

只写 `sync_fifo.v` 的实现，接口已经定好。`tb_sync_fifo.v` 是验收测试，不用改。

## 规格

**握手规则**（AXI-Stream 同款）：
- 发送方拉高 `valid` 表示“我有数据”，接收方拉高 `ready` 表示“我能收”。
- 只有在某个时钟上升沿 `valid` 和 `ready` **同时为 1**，这一拍才算传输成功。

**写入端**（上游 → FIFO）：
- `s_ready = 1`：FIFO 没满。
- 上升沿时 `s_valid && s_ready`：`s_data` 写到队尾。
- **满了就是满了**：即使这一拍下游正好在读，`s_ready` 也为 0。这样实现最简单，验收测试也按这条检查。

**读出端**（FIFO → 下游）：
- `m_valid = 1`：FIFO 非空。
- `m_data`：只要非空，始终等于队头数据。这种方式叫 first-word fall-through，下游不用多等一拍。
- 上升沿时 `m_valid && m_ready`：队头被取走。

**其他**：
- 同一拍可以同时写和读，计数不变。
- `rst` 是同步复位，高电平有效，复位后 FIFO 为空。存储阵列本身不需要复位。
- 参数 `DEPTH` 是 2 的幂，验收测试用 `DEPTH = 16`、`WIDTH = 8`。

## 步骤

1. 先在纸上画结构：一块 `DEPTH × WIDTH` 的存储阵列 `mem`、写指针 `wp`、读指针 `rp`。
2. 想清楚怎么判断空和满。`wp == rp` 时，既可能是空也可能是满，有两种常见解法：
   - 另外维护一个计数器 `count`；
   - 指针多加一位，比较最高位。
   两种都可以，选一种。
3. 写组合逻辑：`s_ready`、`m_valid`、`m_data` 用 `assign`。
4. 写时序逻辑：`always @(posedge clk)` 里处理复位、写入（写 `mem`、移动 `wp`）、读出（移动 `rp`）。时序逻辑一律用 `<=`。
5. 运行 `make`。没通过就运行 `make wave`，从**第一条** FAIL 的时间点开始看波形，不要从最后一条开始。
6. 通过以后回答：如果把“满时也能边读边写”加进来，`s_ready` 要怎么改？它会给时序带来什么问题？提示：`s_ready` 会组合地依赖 `m_ready`。

## 做完的标志

- `make` 打印 `PASS：共写入并按顺序读出 …`。
- 能画出你的 FIFO 结构图，说清空和满是怎么判断的。
- 能解释为什么 testbench 在上升沿之后 1 ns 才改输入。

## 常见错误

- 读写指针用 `DEPTH` 位宽却不回绕，或者回绕时空满判断出错，表现是第 16 个数据左右开始错。
- 在组合逻辑里给 `mem` 赋值，或者时序逻辑里用了 `=`。
- `s_ready` 在满时依赖 `m_ready`，违反了上面的规格。
