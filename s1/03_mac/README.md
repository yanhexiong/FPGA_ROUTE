# S1-03 INT8 乘加单元（MAC）：以 Python 生成参考答案

## 实验目的

神经网络中的卷积、全连接与注意力运算，归结到最底层均为乘加运算 `acc += a * b`。INT8 量化之后，`a`、`b` 为 8 位有符号整数，累加器采用 32 位以避免溢出。S1-04 的脉动阵列即由 4×4 个此类单元构成。

本实验的目标为：

1. 掌握有符号整数的补码表示，以及 Verilog 中有符号运算的规则；
2. 实现一个带同步复位与清零功能的乘加单元；
3. 掌握后续实验将一直沿用的验证方法：以 Python 计算参考答案，在硬件仿真中逐周期比对。

## 背景知识

### 有符号整数的补码表示

计算机中的有符号整数一律采用补码（two's complement）表示，CPU、GPU 与 FPGA 均是如此。本实验的 `a`、`b`、`acc` 均为补码。

N 位二进制数 b<sub>N−1</sub> b<sub>N−2</sub> … b<sub>0</sub> 按补码解释时，其值为：

> 值 = −b<sub>N−1</sub> × 2<sup>N−1</sup> + b<sub>N−2</sub> × 2<sup>N−2</sup> + … + b<sub>0</sub> × 2<sup>0</sup>

即最高位的权重为负，其余各位与无符号数相同。由此可得：

- N 位补码的取值范围为 −2<sup>N−1</sup> 至 2<sup>N−1</sup> − 1。8 位补码为 −128 至 127，32 位补码约为 ±2.1 × 10<sup>9</sup>。
- 最高位为 1 表示负数，因此最高位又称为符号位。
- 求相反数的方法为“按位取反后加 1”。例如 3 = `0000_0011`，−3 = `1111_1100` + 1 = `1111_1101`。

同一组二进制位，按无符号数解释与按补码解释，结果可能不同。二者仅在最高位为 1 时存在差别：

| 8 位二进制 | 按无符号数解释 | 按补码解释 |
|---|---|---|
| `0000_0011` | 3 | 3 |
| `0111_1111` | 127 | 127 |
| `1000_0000` | 128 | −128 |
| `1111_1101` | 253 | −3 |
| `1111_1111` | 255 | −1 |

**导线上传输的只是二进制位，本身并无正负之分；是否按补码解释，取决于设计者的约定。** 在 Verilog 中，这一约定通过 `signed` 关键字声明。

补码得到普遍采用的原因在于：对于加法和减法，有符号数与无符号数可以使用完全相同的电路，结果的二进制位完全一致。二者的区别仅出现在以下几类操作中：比较大小、扩展位宽、乘法以及算术右移。其中与本实验直接相关的是位宽扩展：

- **符号扩展**（sign extension）：将补码扩展到更宽的位宽时，高位用符号位填充，数值保持不变。例如 8 位的 −3 = `1111_1101`，扩展到 16 位为 `1111_1111_1111_1101`，仍为 −3。
- **零扩展**（zero extension）：高位用 0 填充，适用于无符号数。若对 −3 错误地进行零扩展，将得到 `0000_0000_1111_1101` = 253。

乘加运算需要先将 8 位乘积扩展到 32 位再累加，因此必须进行符号扩展。

### Verilog 中的有符号运算

Verilog 默认将所有信号视为无符号数，须以 `signed` 关键字显式声明有符号数。有符号运算遵循以下规则：

1. **只有当表达式中所有操作数均为有符号数时，表达式才按有符号数计算**；只要有一个操作数为无符号数，整个表达式即按无符号数计算，负数将被视为很大的正数。
2. **部分选择与拼接的结果总是无符号数**，即使被选择或拼接的信号本身是有符号数。例如 `a[7:0]` 虽然取出了 `a` 的全部位，结果仍是无符号数。
3. **常数的符号性取决于写法**：不带位宽的十进制常数（如 `0`、`1`）是有符号数；`8'd3` 是无符号数；`8'sd3` 是有符号数。
4. **表达式在运算前，操作数会被扩展到表达式所需的位宽**：有符号操作数作符号扩展，无符号操作数作零扩展。所需位宽由表达式中最宽的操作数与赋值目标共同决定。例如 `wire signed [15:0] p = a * b;` 中，`a`、`b` 先被符号扩展到 16 位再相乘；若声明为 `wire signed [7:0] p`，乘积将被截断为 8 位。

以 `a = −1`、`b = 3` 为例，几种写法的结果如下（已在 Icarus Verilog 12 上验证）：

| 写法 | 结果 | 原因 |
|---|---|---|
| `a * b` | −3 | 两个操作数均为有符号数 |
| `a[7:0] * b` | 765 | 部分选择为无符号数，`a` 被解释为 255 |
| `{1'b0, a} * b` | 765 | 拼接为无符号数 |

### 测试向量的编码

Python 的整数没有固定位宽，−1 并不对应某个 8 位二进制数。因此 `gen_vectors.py` 以 `a & 0xFF` 取出 `a` 的 8 位补码形式（−1 得到 `0xFF`，−128 得到 `0x80`），再写入 `vectors.hex`。`tb_mac.v` 读出这 8 位后，赋给声明为 `reg signed [7:0]` 的 `a`，于是这 8 位重新被解释为 −1。

`vectors.hex` 的每一行对应一个时钟周期，为 13 位十六进制数（共 52 位，使用其中低 50 位），各字段如下：

| 位 | 字段 | 含义 |
|---|---|---|
| 49 | `clear` | 该周期的 `clear` 输入 |
| 48 | `in_valid` | 该周期的 `in_valid` 输入 |
| 47:40 | `a` | 该周期的 `a` 输入，8 位补码 |
| 39:32 | `b` | 该周期的 `b` 输入，8 位补码 |
| 31:0 | 期望的 `acc` | 该周期上升沿之后 `acc` 应有的值，32 位补码 |

## 题目

实现乘加单元 `mac`。`acc` 是本模块中唯一的寄存器；在每个时钟上升沿，`mac` 根据控制信号对 `acc` 执行复位、清零、写入首项、累加或保持操作。

**本题的考查重点是控制逻辑与有符号数的处理，乘法与加法直接使用 Verilog 的 `*` 与 `+` 运算符，无需手工实现乘法器或加法器。** 只要操作数均声明为 `signed`，`a * b` 即得到正确的有符号乘积；综合时，Vivado 会自动将其映射到 FPGA 中专用的乘法单元 DSP48。以门电路搭建加法器、乘法器属于 HDLBits 中 Adder、Multiplier 等题目的内容，有符号乘法器的手工实现算法（如 Booth 算法）亦不在本题范围之内。

### 端口

| 端口 | 方向 | 位宽 | 类型 | 说明 |
|---|---|---|---|---|
| `clk` | 输入 | 1 | — | 时钟。`acc` 只在上升沿更新 |
| `rst` | 输入 | 1 | — | 同步复位，高电平有效 |
| `in_valid` | 输入 | 1 | — | 为 1 时，表示该周期的 `a`、`b` 有效 |
| `clear` | 输入 | 1 | — | 为 1 时，结束当前一轮累加 |
| `a` | 输入 | 8 | 有符号（补码） | 乘数，取值 −128 至 127 |
| `b` | 输入 | 8 | 有符号（补码） | 乘数，取值 −128 至 127 |
| `acc` | 输出 | 32 | 有符号（补码），`reg` | 累加结果 |

### 复位

`rst` 为同步复位，高电平有效。具体要求如下：

1. `rst` 只在时钟上升沿被采样。在某一上升沿处，若 `rst = 1`，则 `acc` 被置为 0。
2. `rst` 由 0 变为 1 时，`acc` 不立即清零，而是在随后的第一个上升沿清零；`rst` 保持为 1 期间，每个上升沿处 `acc` 均被置为 0。
3. 复位具有最高优先级：`rst = 1` 时，`in_valid`、`clear`、`a`、`b` 均被忽略。
4. 复位之后、第一个有效输入到来之前，`acc` 的值为 0。

与之相对的是异步复位：`rst` 一旦为 1，寄存器立即清零，无需等待时钟沿，其写法为将 `rst` 加入敏感列表，即 `always @(posedge clk or posedge rst)`。本实验要求同步复位，敏感列表中只写 `posedge clk`。

### 功能

在每个时钟上升沿，按下表自上而下的优先级更新 `acc`，只执行第一条满足条件的操作：

| 优先级 | 条件 | 操作 | 用途 |
|---|---|---|---|
| 1 | `rst = 1` | `acc ← 0` | 复位 |
| 2 | `in_valid = 1` 且 `clear = 1` | `acc ← a × b` | 开始新一轮点积，写入第一项 |
| 3 | `in_valid = 1` | `acc ← acc + a × b` | 累加 |
| 4 | `clear = 1` | `acc ← 0` | 仅清零 |
| 5 | 其他 | `acc` 保持不变 | 上游没有有效数据 |

补充规定：

- `in_valid = 0` 时，`a`、`b` 的取值无意义，不得影响 `acc`。
- `a × b` 按有符号数计算，并符号扩展至 32 位后参与累加。
- `acc` 溢出时按 32 位补码回绕，与硬件寄存器的自然行为一致。本实验的测试数据不会触发溢出。

### 代码框架

`mac.v` 中已给出模块声明，实现部分须采用如下结构：

```verilog
always @(posedge clk) begin
    if (rst) begin
        // 优先级 1：复位
    end
    else if (/* 优先级 2 的条件 */) begin
        // ...
    end
    // 依次写出优先级 3–5
end
```

注意：时序逻辑必须写在 `always @(posedge clk)` 块中，且一律使用非阻塞赋值 `<=`。`if (posedge clk)` 不是合法的 Verilog 写法。

## 实验步骤

1. 阅读「背景知识」，并核对「示例时序」中每一行的 `acc`。
2. 阅读 `gen_vectors.py`，理解参考模型的计算方式与 `vectors.hex` 的编码。可修改 `SEED` 生成多组测试数据。
3. 按「代码框架」实现 `mac.v`。端口 `a`、`b`、`acc` 已声明为 `signed`；若使用中间变量，同样须声明为 `signed`，例如 `wire signed [15:0] p = a * b;`。
4. 运行 `make`，它将先运行 Python 脚本，再运行仿真。通过时输出 `PASS：2000 拍全部和 Python 参考答案一致`。
5. 若未通过，查看第一条 FAIL 对应的 `a`、`b` 与 `acc`：
   - 若结果为很大的正数，通常是某处操作数被当作无符号数，见「Verilog 中的有符号运算」。
   - 若仅在 `clear = 1` 的周期出错，通常是优先级有误。
6. 通过后进行对照实验：删除中间变量 `p` 的 `signed` 声明，再次运行，观察符号错误的具体表现，然后恢复原代码。

## 常见错误

- 将 `a`、`b` 以部分选择或拼接的形式参与运算，使有符号数变为无符号数。
- 中间变量未声明 `signed`，或位宽不足导致乘积被截断。
- 将 `rst` 写入敏感列表，实现成了异步复位。
- 优先级顺序有误，例如 `in_valid` 与 `clear` 同时为 1 时只执行了清零。
