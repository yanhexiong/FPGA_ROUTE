# S1-03 INT8 乘加单元（MAC），用 Python 生成参考答案

## 为什么做这个

神经网络里的卷积、全连接、注意力，算到最底层都是乘加：`acc += a * b`。
INT8 量化以后，`a`、`b` 是 8 位有符号整数，累加器用 32 位防止溢出。S1-04 的脉动阵列就是把这个单元复制成 4×4 个。

这个实验还会用到后面一直沿用的验证方法：**Python 算参考答案，硬件仿真逐拍比对**。

## 文件

| 文件 | 谁写 | 作用 |
|---|---|---|
| `mac.v` | **你** | 乘加单元，接口已经定好 |
| `gen_vectors.py` | 已给出 | 随机生成 2000 拍输入，用 Python 算出每拍之后 acc 的正确值，写进 `vectors.hex` |
| `tb_mac.v` | 已给出 | 读 `vectors.hex`，逐拍喂给 `mac`，比对输出 |

## 规格

每个时钟上升沿，按下面的优先级更新 `acc`：

| 条件 | 动作 | 用途 |
|---|---|---|
| `rst` | `acc <= 0` | 复位 |
| `in_valid && clear` | `acc <= a*b` | 新一轮点积的第一项 |
| `in_valid` | `acc <= acc + a*b` | 累加 |
| `clear` | `acc <= 0` | 只清零 |
| 其他 | 保持不变 | 上游没数据 |

`a`、`b` 是 8 位补码，范围 −128 到 127。`acc` 是 32 位补码，溢出时按硬件的方式回绕，这个测试不会触发溢出。

## 步骤

1. 先读 `gen_vectors.py`，弄清参考模型怎么算、一行十六进制里各段是什么。可以改 `SEED` 多跑几组。
2. 写 `mac.v`。重点是**符号**：
   - Verilog 里只要表达式中有一个操作数是无符号的，整个表达式就按无符号算，负数会被当成很大的正数。
   - 端口已经声明了 `signed`。中间变量也要声明成 `signed`，比如 `wire signed [15:0] p = a * b;`。
   - 8 位乘 8 位的积用 16 位就够了。想一想为什么。
3. 运行 `make`，它会自动先跑 Python 再跑仿真。通过时打印 `PASS：2000 拍全部和 Python 参考答案一致`。
4. 没通过时，看第一条 FAIL 的 a、b 和 acc：
   - 结果是很大的正数，基本就是符号扩展出了问题。
   - 只在 `clear=1` 的拍出错，是优先级写错了。
5. 通过以后做一个实验：把乘积 `p` 的 `signed` 去掉再跑一次，亲眼看看符号错误长什么样，然后改回来。

## 做完的标志

- `make` 打印 PASS。
- 能解释：8 位 × 8 位为什么需要 16 位；累加器为什么用 32 位。按 ResNet 一层最多累加几千项估算一下够不够。
- 知道 `vectors.hex` 每一位是什么，能自己改 Python 加一种新的测试模式，比如连续 1000 拍都输入 −128 × −128。

## 和后面的关系

- S1-04 脉动阵列：每个 PE（处理单元）就是这个 MAC 再加两个寄存器，把 a 往右传、b 往下传。
- S2：把它综合到 FPGA 上，会看到 `a*b` 被映射到一个 DSP48 上。
