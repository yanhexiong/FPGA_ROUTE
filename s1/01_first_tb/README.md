# S1-01 第一个 testbench：安装仿真工具，完成“编写电路 → 仿真 → 查看波形”的完整流程

## 实验目的

硬件设计中的错误很难在板上定位，因此每个电路都应先在计算机上完成仿真验证，确认无误后再上板。仿真涉及以下三个组成部分：

| 组成部分 | 作用 | 软件中的对应概念 |
|---|---|---|
| 被测设计（Design Under Test，DUT），本实验为 `counter.v` | 待验证的电路 | 被测函数 |
| testbench，本实验为 `tb_counter.v` | 产生时钟、施加激励、与参考答案比对、导出波形 | pytest 测试文件 |
| 仿真器 Icarus Verilog 与波形查看器 GTKWave | 运行 testbench；以图形方式显示各信号随时间的变化 | Python 解释器与调试器 |

testbench 同样以 Verilog 编写，但它没有输入输出端口，仅在仿真器中运行，不会被综合为电路。因此其中可以使用 `#5` 延时、`$display` 打印等仅用于仿真的语法。

## 实验步骤

1. 安装工具（Ubuntu）。安装完成后运行 `iverilog -V`，能够显示版本号即为成功：
   ```bash
   sudo apt install iverilog gtkwave
   ```
2. 进入本目录，运行仿真：
   ```bash
   make            # 等价于以下两条命令
   # iverilog -g2012 -Wall -o sim counter.v tb_counter.v   编译
   # vvp sim                                                运行
   ```
   终端应输出 `PASS：计数、回绕、保持都正确`。
3. 打开波形：运行 `make wave`（或 `gtkwave wave.vcd`）。
   - 在左上方的 SST 面板中展开 `tb_counter`，选中 `dut`。
   - 左下方将列出 `clk`、`rst`、`en`、`q[3:0]`，全部选中后点击 **Append**。
   - 点击放大镜图标「Zoom Fit」，显示完整波形。
   - 右键单击 `q`，选择 Data Format → Decimal，以十进制显示。
4. 对照波形理解 testbench：在波形中找出复位结束的时钟周期、`q` 由 15 回绕至 0 的时钟周期，以及 `en` 变为 0 后 `q` 保持不变的区间。
5. 人为引入错误，观察 testbench 的报错方式：将 `counter.v` 中的 `q + 4'd1` 改为 `q + 4'd2`，再次运行 `make`。testbench 将输出一系列 FAIL 及其发生时刻，请在波形中找到对应时刻。观察完毕后恢复原代码。
6. 在 `tb_counter.v` 中增加一项检查：计数进行到中途时，将 `rst` 置为 1 并保持一个时钟周期，检查 `q` 是否回到 0，同时将参考答案 `golden` 清零。此项须独立完成，不应交由 AI 编写。
7. 运行 `make check`，检验所增加的检查是否有效（见下一节）。

## 检查有效性的验证：`make check`

一项正确的检查须同时满足以下两个条件：

- **无误报**：电路正确时，检查不报错。
- **无漏报**：电路存在错误时，检查能够报错。

`make` 输出 PASS 仅能证明第一个条件成立，因为一项实际上未检查任何内容的代码同样会输出 PASS。`make check` 对两个条件均进行验证。

**分工：实验者只修改 `tb_counter.v`；`counter.v` 与 `mutants/` 目录下的文件均不得修改。** `make check` 会依次将被测设计替换为下表所列的 3 个版本，用同一份 testbench 分别运行，并一次输出 3 项结果：

| 项 | 被测设计 | testbench 的预期结果 | 验证内容 |
|---|---|---|---|
| 1 | 正确的计数器 `counter.v` | PASS | 无误报 |
| 2 | 变异体 M1（复位优先级低于使能）`mutants/M1_rst_after_en.v` | FAIL | 无漏报 |
| 3 | 变异体 M2（复位只生效一次）`mutants/M2_rst_once.v` | FAIL | 无漏报 |

变异体（mutant）是人为引入单处错误的被测设计。两个变异体的错误均位于复位逻辑，原有的 testbench 均无法发现：

| 变异体 | 错误写法 | 原 testbench 无法发现的原因 | 规格要求 |
|---|---|---|---|
| M1 复位优先级低于使能 | 先判断 `en`，后判断 `rst`；`en = 1` 时置位 `rst` 无效 | 初始复位期间 `en = 0`，复位正常生效 | `rst` 具有最高优先级：无论 `en` 取何值，`rst = 1` 之后的下一个周期 `q` 均为 0 |
| M2 复位只生效一次 | 首次复位之后，再次置位 `rst` 均被忽略 | 仅在仿真开始时复位一次 | 任何时刻置位 `rst`，下一个周期 `q` 均为 0 |

所增加的同一项检查须使 3 项结果全部通过，而非针对每个变异体分别编写检查。未通过时，`make check` 将给出原因：

- **第 1 项未通过**：检查本身有误。常见原因是参考答案 `golden` 未随复位清零，或清零时刻相差一个周期。可运行 `make`，查看第一条 FAIL 发生在哪个周期。
- **某个变异体未被检出**：所增加的检查未能覆盖该类错误。请阅读对应文件中的错误写法，对照上表的规格要求，分析检查的遗漏之处。

`make check` 在临时目录中运行，不会覆盖本目录下的 `sim` 与 `wave.vcd`。这种以变异体检验测试有效性的方法称为变异测试（mutation testing），后续实验在编写检查之后，同样可以采用此方法验证。

## 完成标准

- `make` 输出 PASS，并能在 GTKWave 中观察到计数波形。
- 能够说明 testbench 中六段代码各自的作用：实例化、时钟生成、波形导出、复位、逐周期比对、保持检查。
- `make check` 的 3 项结果全部通过：正确的计数器为 PASS，变异体 M1、M2 均为 FAIL。

## 常见问题

- **`make check` 的最后一行为 `make: *** [Makefile:15: check] Error 1`。** 检验未通过时，脚本按惯例返回非零退出码，make 据此输出该行，表示该步骤未通过，并非工具或程序故障。3 项全部通过后，该行不再出现。对于 `make`，testbench 输出 FAIL 后仿真仍正常结束，不会出现该行；该行仅在编译出错时出现。
- **提示 `iverilog: command not found`。** 工具未正确安装，或安装在另一台机器上。
- **波形中的信号显示为红色的 `x`。** 寄存器在复位之前尚未被赋值，此现象属于正常。若复位之后仍为 `x`，说明复位逻辑有误。
- **为何每次检查之前须等待 `#1`？** 在时钟上升沿时刻，寄存器正处于更新过程中；延后 1 ns 读取，才能得到更新后的稳定值。后续所有 testbench 均遵循“在上升沿之后稍作延迟再采样”的约定。
